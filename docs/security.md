# Security

The API is a bearer resource server with no authentication sessions or cookies. It validates RS256 signatures through cached remote JWKS with bounded network timeouts, checks issuer/audience/expiry/required claims, and enforces catalog:write. Public catalog data must remain non-private. New routes require explicit access metadata. Cookies, browser login, tenant data, direct browser consumers, and CSRF/CORS policies require their own design.

Configuration is validated at startup. DATABASE_PROVIDER and URL must agree. Production requires HTTPS identity endpoints, verified database TLS, and disabled API documentation. A file-mounted DATABASE_URL_FILE avoids embedding runtime credentials in Compose environment values. Unknown MySQL URL options are rejected rather than silently weakening TLS or ignoring requested pool behavior. PostgreSQL driver TLS is selected through sslmode=verify-full. Use trusted CA material supported by the selected driver and validate your actual managed service.

Problems expose generic details. Logs never include request bodies, tokens, connection strings, SQL parameters, arbitrary headers, or exception messages/stacks. The server generates request IDs. Prisma query/error logging and Nest startup error dumps are disabled. The frontend validates UUID identifiers and logs only safe failure categories, operation names, and status. Do not enable verbose third-party logging in production without a controlled review.

Scalar is local, same-origin, disabled in production, and configured without telemetry, persisted authorization, or an external proxy. Do not enter client secrets into the API reference. Metrics have a separate unpublished management listener; restrict its network to trusted monitoring clients. Public readiness reveals no database details and liveness is database-independent.

Runtime containers use UID 10001, a read-only root, dropped capabilities, no-new-privileges, bounded resources, and temporary filesystems. The backend JSON parser and Caddy example enforce 64 KB request bodies. Apply distributed rate limits, abuse controls, TLS, and network policy at the production edge according to the product. Current frontend CSP is a baseline; new scripts or analytics need a reviewed nonce policy. React text rendering does not use raw HTML.

The security workflow uses read-only checkout, checksum-pinned Gitleaks with full redaction, and lockfile npm audit including development dependencies at moderate severity. Dependabot and Renovate preserve dependency update automation. The minimatch override retains the source template's reviewed security fix; re-evaluate it when upstream tooling no longer needs it. Runtime/OS image scanning, SBOMs, signing, backup restoration, and production-specific review remain release responsibilities.

Before publication, enable GitHub secret scanning/push protection, Dependabot alerts/security updates, private vulnerability reporting, and branch rules requiring successful CI. Committed workflows do not enable account-level protections or prevent privileged merges by themselves. Review all tracked files/history, author identities, and staged changes. Never publish an archive with private environments, credentials, downloaded agent state, or database data. See [SECURITY.md](../SECURITY.md).
